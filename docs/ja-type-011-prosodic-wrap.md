# JA-TYPE-011 — 意味・発話のまとまりを優先する改行設計

> **ステータス：規則追加のための仕様・検証ケース案。** 現行38規則とv0.1.4-previewのSkills・配布ZIPは未変更です。本文節解析器／発話境界検出器が実装済みであるとは主張しません。

## 目的

日本語の見出し・短い説明文・UIラベルでは、単語や文節で切ることが形式上可能でも、それが発話上の自然な区切りとは限りません。**複数の文節をまとめた意味上の強い結び付き**と**読み上げるときの自然な間**を優先した行分けを選び、必要な表示幅をレイアウト側で確保します。

元の文字列：`いつものAIツールからはじめよう`

**第一候補（成立する表示幅がある場合）**：

```text
いつものAIツールから
はじめよう
```

**低優先（文節ごとに細かく切りすぎる）**：

```text
いつもの
AIツールから
はじめよう
```

**避けるべき分割**：

```text
いつものAIツールか
ら
はじめよう
```

「いつもの」と「AIツールから」は文節境界では区切れても、このコピーでは修飾関係と発話の流れからまとめる方を優先します。例示は万能の二行テンプレートではなく、文脈と幅の条件付きです。

## 判断順位

1. **内容の不変・読み順・操作可能性（必須）**：名前、文字、助詞、数値、句読点を変更しない。原文への可視スペース挿入や一律の省略をしない。
2. **禁則処理（必須）**：既存 `JA-TYPE-002` と組み合わせ、実際に表示された行頭と行末を確認する。禁則と意味上の不自然さは別項目で判定する。
3. **意味上の結び付き（優先）**：修飾語＋被修飾語、名詞句＋助詞、固有名詞、複合述語を考慮し、文節境界を機械的に改行許可とは扱わない。
4. **発話の自然な間（優先）**：通常の朗読で大きく間を置く位置を検討し、その境界を候補として優先する。強調の意図が違えば別の候補もあり得る。
5. **行の見た目（比較）**：極端に短い行、一文字孤立、視線移動を比較する。均等な行長のために意味を分断しない。
6. **表示幅とアクセシビリティ（必須）**：実フォント、320 CSS px相当、文字200%拡大、文字間隔変更時にも欠落・隠蔽・不適切な横スクロールがないことを確認する。

## レイアウト先行の解決

**現在の狭い枠へ無条件に文字を押し込まず、まず望ましい行分けを考えてから枠を調整します。** カラム比率、余白、グリッドのgap、配置、見出しのローカルな文字サイズを順に検討し、文言の勝手な書換えや全文の小さな字への圧縮は避けます。成立しないほど狭い場合は、一段低優先の改行を許容して表示内容と操作性を守り、妥協と未確認事項を記録します。

## 媒体別適用

| 対象 | 推奨 | 注意点 |
| --- | --- | --- |
| H1/H2/キャッチコピー | 意味・発話単位を重視し、複数候補を比較 | 二行固定・全文 `nowrap` の強制は不可 |
| UIラベルと短い案内 | 自然なまとまりと操作可能性を両立 | 長いラベルの切り取りを禁止 |
| 本文・記事 | 通常の日本語改行と禁則を基本に局所レビュー | 全段落を発話単位で分割禁止にしない |
| Word/PDF | 行長・テキスト枠・見出し配置を調整して実表示を確認 | 禁則の設定だけでは意味単位は保証されない |
| PowerPoint | 見出しの意図を読んでテキスト枠と周囲の構成を調整 | 内容移動・一律縮小は避ける |

## 技術と証跡

- Webでは `lang="ja"`、`line-break: strict` に加え、対応環境で `word-break: auto-phrase` や `text-wrap: balance` を**補助的に**使える。ただし、ブラウザが選ぶ文節付近のフレーズ境界は、今回優先する複数文節にまたがる発話単位と必ずしも一致しない。
- 必要なら確認済みの意味上の境界に局所的な `<wbr>` を置く。これは他の箇所の改行を絶対に禁止しない。文字列の可視スペース、無条件 `word-break: keep-all`、段落全体の `white-space: nowrap`、隠すための `overflow: hidden` を用いない。
- 規則適合性は、`assisted`（意味・係り受け・発話上の判断）と `rendered`（実際の行分け・行端・表示領域・操作性）を別々に記録する。ブラウザのCSS宣言やAI推論だけで全環境 `passed` とはしない。
- 検証対象と優先候補は [`ja-type-011-cases.json`](ja-type-011-cases.json) に収録する。好ましい候補も原文の文字列が完全に同一でなければならない。

## 現行規則との接続とリリース境界

- `JA-TYPE-002`：禁則を独立して維持。
- `JA-TYPE-003`：分割しない範囲を文脈で判断。
- `JA-TYPE-004`：意味のまとまりと禁則を別に評価。本仕様は意味判断を**複数文節にまたがる発話単位とレイアウト設計**まで具体化。
- `JA-TYPE-009`：行長・行送り・字間・実フォントを考慮。
- `WEB-001`〜`WEB-005`：狭い表示、文字拡大・間隔変更、長いラベル、クリッピング防止を確認。

**この文書の追加だけでは `JA-TYPE-011` は現行Skillsに有効化されません。** 次工程でcanonical `skills/kumihan/rules/`、四つの独立 Skills とprofiles、ケースID、inventory、配布ZIP・各マニフェストを同期し、`tools/build_dist.py --check` と実レンダリング・独立レビューを通して正式導入します。
