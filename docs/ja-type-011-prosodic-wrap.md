# JA-TYPE-011 — 表示幅と文字サイズから判断する改行設計

> **実装中：JA-TYPE-011 ソース候補。** 正式配布には4 Skills、inventory・ZIP・manifest・バージョン・実レンダリングの検証とレビューが必要です。形態素解析器や発話境界検出器を実装したという意味ではありません。

## 目的

日本語の見出し・短い説明文・UIラベルは、内容保持・禁則・アクセシビリティを守り、実際の有効幅と実効文字サイズ、フォント、周囲の構成から意図的な改行の必要性を先に判断します。自然に一行で収まる場合、承認された表現意図がなければ改行を追加しません。折り返す場合は行全体のバランスと読みの流れを比較し、意味・発話のまとまりは物理的に成立し改善する条件で選択します。文節ごとの改行は義務ではありません。

元の文字列：`いつものAIツールからはじめよう`

**第一候補（成立する表示幅がある場合）**：

```text
いつものAIツールから
はじめよう
```

**低優先（文節ごとに細かく切りすぎる）**：

```text
いつもの
AIツールから
はじめよう
```

**避けるべき分割**：

```text
いつものAIツールか
ら
はじめよう
```

「いつもの」と「AIツールから」は文節境界では区切れても、このコピーでは修飾関係と発話の流れからまとめる方を優先します。例示は万能の二行テンプレートではなく、文脈と幅の条件付きです。

## 判断順位とレイアウト先行の解決

1. **必須条件**：元の文字列・読み順・選択／コピー・操作性・禁則を維持する。隠蔽・切捨て・意図しない横スクロールを避ける。
2. **実表示を測る**：viewportだけでなくinline content width、computed font-size、実際に使用されたフォントとfallback、拡大方式、字間、周囲の余白を記録する。幅÷文字サイズは条件の記述であり、採否の普遍的な閾値ではない。
3. **意図的な改行が必要か判断する**：通常折り返しを基準に、自然な一行表示や自動reflowが妥当なら文節ごとの改行を加えない。固定二行にしない。
4. **成立する意味単位を比較する**：複数文節のまとまりが収まり、行全体と読みの流れを改善する場合に優先する。必要ならカラム比率・gap・余白・配置を検討するが、常に句を守るために枠や字を変えることを義務にしない。
5. **狭幅／大文字時**：320px＋CSS 200%など、意図したまとまりが成立しない条件では不要な作者側改行制御を外す案を優先し、normal、balance、auto-phrase、併用を実描画で比較する。通常折り返しも形態的に理想とは限らず、未解決ならneeds-reviewとする。
6. **全行と周囲を評価する**：行数・各行の実幅・行長の差・短い中間行・末尾1字・読み順・周囲の空白・操作性を比較する。末尾1文字だけの解消や機械的な均等化を合格条件にしない。

文字列に可視スペース・ゼロ幅文字を挿入しない。全文nowrap、block spanやbrによる文節ごとの強制改行、max-content、クリッピング、一律縮小、固定フォント指定を一般解にしない。承認済みの局所的な表現意図は記録し、安全条件と両立しない場合に再確認する。

## 媒体別適用

| 対象 | 推奨 | 注意点 |
| --- | --- | --- |
| H1/H2/キャッチコピー | 意味・発話単位を重視し、複数候補を比較 | 二行固定・全文 `nowrap` の強制は不可 |
| UIラベルと短い案内 | 自然なまとまりと操作可能性を両立 | 長いラベルの切り取りを禁止 |
| 本文・記事 | 通常の日本語改行と禁則を基本に局所レビュー | 全段落を発話単位で分割禁止にしない |
| Word/PDF | 行長・テキスト枠・見出し配置を調整して実表示を確認 | 禁則の設定だけでは意味単位は保証されない |
| PowerPoint | 見出しの意図を読んでテキスト枠と周囲の構成を調整 | 内容移動・一律縮小は避ける |

## 技術と証跡

- Webでは `lang="ja"`、`line-break: strict` に加え、対応環境で `word-break: auto-phrase` や `text-wrap: balance` を**補助的に**使える。ただし、ブラウザが選ぶ文節付近のフレーズ境界は、今回優先する複数文節にまたがる発話単位と必ずしも一致しない。
- 必要性と実描画上の改善が確認できる場合のみ、確認済みの境界に局所的な `<wbr>` を検討する。不要なら追加せず、既存の作者側制御も対象条件で再評価する。これは他の箇所の改行を絶対に禁止しない。文字列の可視スペース、無条件 `word-break: keep-all`、段落全体の `white-space: nowrap`、隠すための `overflow: hidden` を用いない。
- 規則適合性は、`assisted`（意味・係り受け・発話上の判断）と `rendered`（実際の行分け・行端・表示領域・操作性）を別々に記録する。ブラウザのCSS宣言やAI推論だけで全環境 `passed` とはしない。
- 検証対象と優先候補は [`ja-type-011-cases.json`](../tests/contracts/ja-type-011-cases.json) に収録する。好ましい候補も原文の文字列が完全に同一でなければならない。
