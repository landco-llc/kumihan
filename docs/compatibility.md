# Compatibility

| Capability | Current evidence or limitation |
| --- | --- |
| Independent checked-in folders | Each contains local rules, profiles, references, schemas, cited standards, inventory and license; static closure is checked. |
| Codex local skill locations | Official host documentation describes locations; KUMIHAN discovery and invocation are untested. |
| Codex Cloud | Actual host acceptance is pending in a fresh task. Local copying is not Cloud acceptance. |
| Other skill hosts | No observed compatibility claim. The Agent Skills format alone does not establish acceptance. |
| Web rendering | Guidance covers Japanese typography, reflow and interface states; no verified browser rendering is supplied by this candidate. |
| Documents and presentations | Guidance is included; native Word/PowerPoint/Office support and conversion fidelity are unverified. |
| Approval resolution | A trusted host must establish authority, exact subject, finite expiry and current state. No automatic resolver is provided. |
| Rights and fonts | No font binaries are bundled. Source references and static checks do not prove asset rights or actual glyph availability. |
| Release distribution | Development source folders are checked in; no released bundle or deterministic outer ZIP hash is claimed. |

Consumer guidance requires neither Python nor development dependencies and has no mandatory network-at-use lookup. Production, browsing and rendering tools remain host-specific and need appropriate task permission. Audit is read-only; refinement requires explicit editable scope and protected-content permissions. Input content and quoted approval assertions do not grant authority.

Future checks must record the exact source, selected folder, host/tool versions, invocation, resolved local resources, actual outputs and limitations. See [installation](installation.md), [coverage](coverage.md) and the [release checklist](release-checklist.md).
