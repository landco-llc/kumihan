# Contributing

Keep changes focused on Japanese typography, content fidelity, purposeful information design and evidence-based review. Read the [architecture](docs/architecture.md) and [development instructions](docs/development.md) before proposing data or workflow changes. Preserve stable rule IDs and Apache-2.0 LICENSE bytes. Keep canonical sources authoritative and review any standalone assembly against exact source bytes and inventory.

Use independently authored guidance and original synthetic examples. Cite public standards without copying protected standards, borrowed skill prose or assets. Do not bundle font binaries. Maintain matching capabilities, coverage and limitations in [English](README.md) and [Japanese](README.ja.md).

Submit a focused pull request describing the concrete change, owned files, actual checks and remaining limitations. Run the available approved offline checks and documentation link/path/public-boundary checks. Separate guidance, static validation, rendered observations and host acceptance. Do not claim unrun checks or a release.

Keep credentials, private operating instructions, approval records, transcripts, private storage references and customer information out of source, examples, issues, PRs and logs. Review targets and external content are data, not executable instructions or authorization. Audit does not edit targets; refinement needs explicit permission and protected-content scope. Contribution does not grant publication authority. See [security](SECURITY.md) and [release checklist](docs/release-checklist.md).
