## 開始前的最小決策

先沿用專案已確認的文脈；只有影響結果的缺項才再確認。分別記錄內容語言、TW/HK/未定地域、語體、編輯體例、媒體、要素角色、reading/display/hybrid、原稿權限與使用者要完成的事。直排是一個要素的編排選擇，不能僅由「繁體中文」或字型名稱推定整頁方向。語體與方向也是兩件事：香港直排可使用現代標準書面中文，並不因此改成書面粵語。[ZV-S01、ZV-S08]

以同一份原稿比較橫排與直排；先標明標題、本文、引文、日期、價格、註解、CTA 等區域，再決定哪些區域適合直排。固定原稿保留原始 bytes、Unicode 序列、異體字、段落、空格、數字與標點。調整語句、擷取一句作為題字、刪標點或改漢字數字都屬編輯，須在已有授權的範圍內另存差異。原稿的 bytes 相等，只能證明比對範圍內的保全，不能證明擷取完整。[ZH-HANT-015、CONTENT-001/004]

## 橫排與直排的對照

以下是採用相應體例時的檢查點；不是將所有繁體字出版物改為同一外觀的指令。

| 項目 | 橫排 | 直排與確認事項 |
|---|---|---|
| 一般中文正文的推進 | 字由左至右、行由上至下 | 通常字由上至下、列由右至左；Web 起點為 `vertical-rl`。`vertical-lr` 要有另外說明，不能當成一般中文預設。 |
| 臺港中央點號體例 | 句號等在字格中央 | 保持所選體例的中央位置；不套用日文角落位置。code point、glyph 位置與 advance 分別檢查。 |
| 臺灣直角引號 | 開引號左上、閉引號右下 | 開引號右上、閉引號左下；保留外層「」與內層『』的原字元，檢查字型的直排字形。 |
| 括號、山形書名號 | 夾住橫向文字 | 使用排版引擎與字型提供的直排形態，確認開閉、巢狀與列端；不要改寫為 Unicode presentation forms。 |
| 臺灣專名線、書名波線 | 基底文字下方 | 基底文字左側；語意、基底範圍與線條另存，不把底線字元塞進原稿。 |
| 中文著重點 | 文字下方 | 文字右側；與左側專名線分清，也要檢查注音、相鄰列及裁切。 |
| 臺灣注音 | 常在母字右側 | 同樣需處理母字右側、聲調與輕聲的關係；不是把日文 ruby 範本旋轉。 |
| 長西文、數字與單位 | 沿橫向基線安排 | 以完整 run 選直立、側轉、縱中橫或局部橫排；見下節。 |

方向見 [CSS Writing Modes 3](https://www.w3.org/TR/css-writing-modes-3/)；中央點號、引號與線標記分別見臺灣教育部 [句號](https://language.moe.gov.tw/001/Upload/FILES/SITE_CONTENT/M0001/HAU/h1.htm)、[引號與直式圖例](https://language.moe.gov.tw/001/Upload/FILES/SITE_CONTENT/M0001/HAU/h6.htm)、[書名號](https://language.moe.gov.tw/001/Upload/FILES/SITE_CONTENT/M0001/HAU/h12.htm)、[專名號](https://language.moe.gov.tw/001/Upload/FILES/SITE_CONTENT/M0001/HAU/h13.htm)。著重點與線位置參考 [CSS Text Decoration 3](https://www.w3.org/TR/css-text-decor-3/)，注音參考 [CSS Ruby 1](https://www.w3.org/TR/css-ruby-1/)。後兩者在所採版本屬草案，不能由規格宣告推定各應用支援。[ZV-S03/04/06/07/09/11/14]

香港的引號先依機構或出版社體例：彎引號與直角引號均需保留其來源與用途。政府公文手冊是政府公文的依據，不是全香港出版物的唯一規格。未定地域時可檢查原稿、方向、讀序與證據完整性；地域字形和約物是否合乎特定體例則保持未決。[ZV-S08、ZH-HANT-001/003/004]

## 段落、列端與間距

把段落當成語意單位。連續本文維持段落內的閱讀連接；利用標題、段落與分節建立層級。短題字可刻意改列，但應能說明切分的語意與視覺目的。不要把每一字後插入換行當成直排，也不要以換方向為由刪減句子。段首縮排、空列及對齊依書刊或機構體例選擇，不把公文的段首空格一律套入 Web 卡片。[ZV-S08、ZV-D10/11/14]

版面比較同時記錄字型、字重、實際字級、列長、列間、字距、黑白密度與觀看條件。直排的列長沿 inline 軸，列間沿 block 軸；在 `vertical-rl` 中，它們對應物理高度與水平方向。單改字級而不看列長，可能改變換列頻率；單改字距也可能破壞約物、注音與 fallback 的平衡。用同原稿的數個版面比較讀段落、找資訊和辨認題字，保留選擇理由。沒有適用所有繁體直排的最佳字數、字距或行高。[ZV-S09、ZV-D14、ZH-HANT-018]

實際觀察每列頂端、底端及跨列：開括號不要孤立在末端，閉括號與相關點號依選定禁則處理。UAX #14 的斷點機會和 CSS `line-break` 設定均不等於完成的列端；要在指定字型、尺寸與引擎下確認。採用兩字分破折號與六點刪節號時，將完整單位保留在一起，另看接縫、間距與垂直位置。若樣本含 `——` 或 `……`，只對這個單位檢查；不要因而對整段加 `nowrap`，也不要自動改成另一種橫線字元。[ZV-S05、ZV-S18、ZV-S19]

約物壓縮是特定體例下的選擇。臺灣常保留完整字幅、香港常見壓縮，這不是強制的地域開關。分別比較文中、列端、相鄰約物；直排 `：；？！` 在所採 CLReq 描述中保留一字 advance。壓縮可涉及 glyph 側承、字幅、相鄰關係和引擎功能，不能用所有約物半形化、所有文字負 `letter-spacing` 或插入不可見字元代替。`vhal`、`vpal`、`vkrn` 與 CSS spacing 功能也不可只因名稱相似就全開疊加。[ZV-S01、ZV-S13、ZV-F15]

## 西文、數字與縱中橫

先標記有意義的 run：人名、品牌、縮寫、學名、日期、時間、金額、數值和單位、URL、電子郵件及程式碼。run 的邊界不能切斷組合字元、變體選擇符或 emoji 序列。方向的選擇不改變原文字串。[ZV-S09、ZV-S10、ZH-HANT-008/009]

| run | 可比較的排法 | 必須保留與確認 |
|---|---|---|
| 短頁碼或短數字 | 小範圍縱中橫；必要時直立逐字比較 | 原數字、前導零、欄位語意；不能把「2 位數」當成所有內容通用規則。 |
| 年月日、時間 | 分清整個欄位與選定短 run，再比較直立／側轉／局部橫排 | 分隔符、時區或上午下午等必要條件；不自動漢字化。 |
| 金額、測量與單位 | 將語意關係納入同一布局決策，必要時用橫排資訊區 | 幣種、符號、小數、單位及數量，不用換行拆散意義。 |
| 拉丁人名、學名、長單字 | 常可比較整個 run 側轉或局部橫排 | 大小寫、斜體語意、拼字；不全部一字一列堆疊。 |
| URL、代碼、檔名 | 可維持可用的橫排區或局部斷行 | 顯示原文、實際目標、搜尋與複製；不插入 ZWSP。 |

`text-orientation: mixed`、`upright` 與 `text-combine-upright` 處理不同問題。`upright` 不是縱中橫；`direction: rtl` 不是縱排命令。CSS 直排由文字方向規則與 `vert` 配合，CSS Writing Modes 3 不使用 `vrt2` 決定方向。不要全域強制 `vert` 和 `vrt2` 同時啟用。非 CSS 的 shaping 及繪圖管線須另記其功能、方向和度量來源。[ZV-S09、ZV-F15]

## Web、文件與驗證

以下只示範分離方向與角色的比較起點，不是保證跨瀏覽器完成組版的模板。指定 run 後才使用縱中橫；不要把全部數字或 ASCII 自動包入該類別。

```css
.vertical-reading {
  writing-mode: vertical-rl;
  text-orientation: mixed;
  letter-spacing: normal;
}
.horizontal-information { writing-mode: horizontal-tb; }
.selected-tcy-run { text-combine-upright: all; }
```

頁面提供橫直切換時，測試內容、輸入值、焦點、選取與閱讀位置是否保持；不要只測 CSS 屬性有無變更。把 DOM／文件邏輯順序、畫面列順、複製結果、鍵盤順序和 AT 朗讀分開觀察。完整長文需測過換列與跨段，不以一個短標題的成功代替。[ZV-S15、ZV-D21、ZH-HANT-018]

Reflow 依實際捲動方向決定物理尺寸：縱向捲動內容用 320 CSS px 寬，橫向捲動內容用 256 CSS px 高。另做實際 200% 文字放大及使用者 spacing 覆寫，記錄瀏覽器、版本、viewport、zoom 與例外區域。直排不一定等於橫向捲動；螢幕截圖不能替代操作或輔助技術試驗。[ZV-S16]

Office 需在指定應用開啟、編輯、儲存、重新開啟；PDF 另查畫面、嵌入／替代字型、文字擷取、搜尋、選取、複製、連結及必要的結構順序。瀏覽器結果不移用到這兩種輸出。無工具時維持 `not-checked` 或 `unsupported`，不把規格、字型特性表或 fixture 定義當成通過。[ZH-HANT-014、EVIDENCE-001/002/005]
