# 直排字型：來歷、實例與證據

## 選字型的順序

先確定本文／題字角色、臺港編輯體例、所需字元、字級與觀看條件，再選可用且授權範圍合適的字型。明體、黑體、楷體或手寫風格都不是直排專用的合格標章；同一家族的不同字重、Text/Display 分支、子集或版本也可能有不同表現。[ZV-F09/10/12/13/14]

檢查實際檔案而非 CSS family 名：記錄來源 URL、檔名、配發 tag、內部 name/version、SHA-256、face index、variable axes、子集與觀察到的 fallback。記錄文字的語言標記與引擎；不要把「指定的字型」當成「實際畫出的字型」。是否涵蓋所需字元、選出的地域 glyph 是否合乎體例、約物位置是否正確，各自判斷。[ZH-HANT-016]

## 來歷對選用的提示

| 候選或系統 | 來源記載的形成方式 | 可用來提出的比較；不構成直接合格 |
|---|---|---|
| 蘭陽明體 | justfont 從《澗于集》等民初雕版楷書得到線條與字形的設計線索，再形成現代明體。 | 可比較文字韻律、字面與字重在本文和題字的表現；不把單一產品史寫成所有明體的歷史。 |
| 日星宋體貳號 | 銅模修復與數位整理之間需要重建可用的字形、細節和現代組版條件。 | 活字來源可以是表現依據；現代直排的約物、缺字與印刷實寸仍需另驗。 |
| 金萱 | 製作者以明體與黑體之間的造形探索，並為尺寸和用途修整。 | 可比較短本文與展示文字的柔硬、黑白密度；不是固定的「高級感」開關。 |
| 北魏真書 Zansyu | 製作者研究碑刻與香港招牌文化，整理成當代標題字庫。 | 可用於題字與文化引用的方案比較；長文閱讀、粵語字覆蓋和授權另查。 |
| 思源宋體／思源黑體、Noto CJK | 泛 CJK 系統有地域資源與相應配發方式；香港資源不能與 TC 名稱混為一談。 | 選對實際 TC/HK 檔案、語言系統和所需字形；名稱或 `locl` 標籤不是完整證據。 |
| 昭源宋體 Chiron Sung HK | 作者針對香港印刷體慣行選擇字形，並區分與標準手寫形的關係；另有本文用途分支。 | 在 HK 本文、粵語字和稀有字中比較字形與黑度；仍須實檔、實文字及實引擎確認。 |
| 芫荽 Iansui | 從 Klee One 衍生，針對臺灣學習用途及台客語等需求補整。 | 可比較教育、注音與親近語氣的文字；不可假定覆蓋全部香港粵語用字。 |
| 文鼎書苑宋 Text / Display | 產品把小本文的清晰與大字細節分開設計。 | 題字和本文可分別選型，不從字級大小直接推定內容角色。 |

以上是製作者或官方文件中的具體來歷，並非效果保證。完整來源為 ZV-F01–F14；F04/F06/F08/F13/F14 的研究觀察僅及官方搜尋摘要，不能描述為已檢視字型二進位或全部字樣。候選需要在專案現有字型中比較，不強制購買或更換。[來源台帳](../sources/public-sources.json)

## 字型技術的不同層

| 層 | 問題 | 可用證據與限制 |
|---|---|---|
| 字元涵蓋 | 所需 code point／sequence 能否找到候選 glyph？ | cmap、實際 shaping 與缺字報告；cmap 有字不保證地域形正確，IVS 另查。 |
| 地域字形 | 此文字、語言標記與編輯體例選到什麼形？ | 具體 glyph、language system、`locl` lookup 與畫面；`locl` 存在不代表自動地區切換。 |
| 縱向度量 | 直排的 advance、bearing、原點是否成立？ | `vhea`／`vmtx`、引擎合成規則與位置觀察。`VORG` 是 CFF/CFF2 的任意表；TrueType 不含它並不自動失敗。 |
| 直排替代字形 | 括號、引號等選到哪個 glyph？ | `vert` lookup、字形輸入輸出及引擎。CSS 與非 CSS 的方向分工分開記錄。 |
| 間距調整 | 實際改變字幅、鄰接間距還是字形？ | 比較 `vhal`／`vpal`／`vkrn` 等功能的實際結果；不以 tag 存在代替測量。 |
| 輸出 | 看得見、找得到、可複製、能操作嗎？ | 指定瀏覽器／Office／PDF viewer 的結果；靜態 font inspection 不能回答所有問題。 |

規格依據：[OpenType features u–z](https://learn.microsoft.com/en-us/typography/opentype/spec/features_uz)、[vmtx](https://learn.microsoft.com/en-us/typography/opentype/spec/vmtx)、[VORG](https://learn.microsoft.com/en-us/typography/opentype/spec/vorg)、[locl](https://learn.microsoft.com/en-us/typography/opentype/spec/features_ko)。CSS 的直排依 [Writing Modes 3 §5.1](https://www.w3.org/TR/css-writing-modes-3/#text-orientation) 處理；不要同時全域強開 `vert` 與 `vrt2`。[ZV-F15–F18、ZV-S09]

## 版本與過往修正如何使用

芫荽曾有直排標點偏移的維護紀錄，昭源宋體也有直排引號／書名號的回報與修正紀錄。這些資料能提示要檢查的條件，不能作為今天所有應用已合格或整個家族有缺陷的證明。先識別取得的檔案，再重現相同文字與方向；若不能重現，就保留環境差異與未確認部分。[ZV-F19、ZV-F20]

研究取樣中，芫荽配發 tag `v1.020` 與字型內部 `Version 1.012` 是不同欄位；昭源宋體取樣為 `1.024` 的 static Regular。這說明「配發名稱」不可代替內部版本與 digest。曾對特定樣本做過靜態解析和低層 shaping，不等於本版 30 個 fixture、瀏覽器、原生 Office 或輔助技術已通過。字型原檔未作為此套件的指定依賴或內嵌資產。[ZV-F21、ZV-F09/10]

最終以同一份原稿作橫直對照，至少涵蓋中央點號、成對括號、兩字分破折號／刪節號、所需罕字、Latin run、數量單位及實際採用的注音。改字型、子集、引擎或字級後，重驗受影響的項目。未取得實際 fallback 或 glyph 證據時，可以報告畫面觀察，但不要宣稱已通過地域字形或 IVS 判定。[ZH-HANT-002/006/008/012/013/016、EVIDENCE-005]
