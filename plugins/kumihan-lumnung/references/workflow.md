# Workflow / ដំណើរការការងារ

1. Identify purpose, audience, medium and explicit locale km or km-KH before applying rules.
2. Preserve all original Khmer text and code point order; any change requires a separate proposed diff and permission.
3. Read rules/catalog.json (KM-01..KM-30), fixtures/acceptance.json (T01..T24), locales/km-KH.json and sources/public-sources.json.
4. Review language, type hierarchy, line breaking, font support, spacing, mixed scripts and purpose-driven layout—not generic AI patterns.
5. Report source spans, rule IDs, evidence status (observed / needs-review / not-checked), impact and proposed fix.
6. Escalate lexical breaks, punctuation, native idiom, CTA tone and logo shaping for Khmer native-editor review.
7. Check practical environments; never claim browser/Word/PowerPoint/native-provider success without observation.
